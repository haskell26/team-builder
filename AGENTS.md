# Project Workspace Rules

This workspace is generated by the harness. The source of truth for intent lives in `.harness/`.

## Priorities

1. Implement the spec in `.harness/spec.md`.
2. Follow the plan in `.harness/plan.json`.
3. Address any `.harness/qa-round-*.json` blockers before adding new scope.
4. Leave the workspace readable for future agent passes.

## Rules

- Prefer complete, coherent behavior over broad but shallow scaffolding.
- Avoid placeholder features, fake integrations, and TODO-only delivery unless the spec explicitly allows them.
- If you must cut scope, document the cut clearly in `FINAL_OUTPUT.md`.
- Keep setup and verification steps current in `README.md`.
- Add tests or executable checks when the project contains logic that can be verified.
- Do not claim functionality without verification evidence.
