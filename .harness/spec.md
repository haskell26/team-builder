# Team Builder

## This Iteration

이번 실행은 기존 후보 조합 기능을 확장하는 3차 개발이다.
기존 입력/팀 분배/후보 조합 기능은 유지한다.
후보 조합은 같은 역할군 간 밸런스도 맞아야 하며, 특히 탱커 밸런스를 더 중요하게 본다.
이번 우선순위는 후보를 빠르게 비교할 수 있는 compact preview UI 와, 후보를 불러온 뒤 직접 수정할 수 있는 스왑 편집 기능 추가이다.
이번 실행에는 플레이어별 역할 선호도 순서 적용, 플레이어 티어 저장, 저장된 플레이어 중 10명 선택 기능도 현재 iteration 범위에 포함한다.
기존 QA에서 남은 브라우저/모바일 실기기 검증 미완료는 이번 라운드에서 blocker로 간주하지 않는다.
점수는 내부 계산용으로만 유지하고, 메인 UI 에서는 전반적으로 숫자 점수 표기를 하지 않는다.

## Goal

각기 다른 실력을 가진 게임 플레이어 10명이 모였을 때, 밸런스가 맞는 두 팀으로 나누기

## Users

- Who is the primary user?
오버워치 게임 커뮤니티의 관리자
- What problem are they solving?
커뮤니티 내 정해진 플레이어 10명을 밸런스한 두 팀으로 나눠야 한다.

## Core Flows

유저가 데이터를 다음 형식으로 엑셀로부터 복사해와서 붙여넣는다.
|유저 이름|탱커 티어|딜러 티어|힐러 티어|
|...|
그러면 각 티어별로 점수를 할당해서 점수의 총합이 양팀이 가장 적게 차이가 나야 한다. 각 팀은 탱커 1명, 딜러 2명, 힐러 2명으로 구성된다. (Unranked는 양팀에 최대한 비슷하게 분배돼야 한다.)
U 0점 (Unranked)
브론즈 1점
...
다이아 5점
마스터 6점
그마 7점
github.io로 올릴 수 있게 프론트엔드만으로 구성된 프로젝트여야 한다.

## Must-Have Features

- user friendly input (copy-paste from excel)
- nicely-readable output
- product language in korean
- 가능한 후보 조합 6개 생성
- 후보 조합 6개를 한눈에 빠르게 비교할 수 있는 compact preview UI 제공
- 각 후보 preview 에서 팀 A / 팀 B 구성과 역할 배치를 작은 카드 형태로 보여주기
- 플레이어 티어는 이름 또는 이름 배경색으로 직관적으로 표현
- 티어 색상 규칙:
  - 언랭: white
  - 브론즈: bronze
  - 실버: silver
  - 골드: gold (yellow)
  - 플래티넘: mint
  - 다이아: blue
  - 마스터: green
  - 그랜드마스터: violet
- 후보 조합은 다음 우선순위로 정렬:
  1. 총점 차이 최소
  1-1. 총점 차이가 같으면 역할군별 점수 차이 합이 더 작은 후보를 우선한다.
  1-2. 역할군별 점수 차이 합도 같으면 탱커 점수 차이가 더 작은 후보를 우선한다.
  2. 언랭 분배 차이 최소
  3. 1, 1-1, 1-2, 2가 모두 같으면 랜덤하게 정렬
- 사용자가 후보를 선택하면 해당 후보를 최종 편집 영역으로 불러와야 한다.
- 최종 편집 영역에서는 사용자가 플레이어를 직접 클릭해서 서로 스왑할 수 있어야 한다.
- 스왑은 두 슬롯을 차례대로 클릭하면 수행된다.
- 스왑 이후 화면은 즉시 갱신되어야 한다.
- 점수는 내부 계산에만 사용하고, 메인 UI 에서는 개인 점수 / 팀 총점 / 숫자 점수 차이를 기본적으로 표시하지 않는다.
- 플레이어별 역할 선호도 순서를 입력하거나 수정할 수 있어야 한다.
- 후보 계산과 최종 편집은 역할 선호도 정보를 반영할 수 있어야 한다.
- 플레이어 티어 정보를 저장할 수 있어야 한다.
- 저장된 플레이어 목록에서 이번 매치에 사용할 10명을 선택해서 불러올 수 있어야 한다.
- 입력 헤더 행은 optional 이다. 있어도 되고 없어도 된다.

## Interaction Rules

- 후보 preview 는 빠르게 비교하는 용도이므로 작은 카드/요약 형태여야 한다.
- 최종 편집 영역은 선택된 후보 1개만 대상으로 한다.
- 사용자가 첫 번째 슬롯을 클릭하면 선택 상태가 표시되고, 두 번째 슬롯을 클릭하면 두 슬롯의 플레이어가 서로 교체된다.
- 스왑은 역할 슬롯 기준으로 이루어진다. 즉, 플레이어가 슬롯을 교체하면 해당 슬롯의 역할을 따른다.
- 점수 숫자는 메인 UI 에서 숨기되, 내부 계산과 후보 정렬 로직은 유지한다.

## Nice-To-Have Features

- 현재는 오버워치만 다루지만 추후 리그오브레전드로 확장될 가능성 있음

## Technical Constraints

- Preferred language or framework: frontend
- Required integrations
- Deployment assumptions: github.io로 프론트엔드만 배포 예정
- Anything the agent must avoid: 복잡한 UX
- 헤더 행은 있을 수도 있고 없을 수도 있다. 둘 다 지원해야 한다.

## Acceptance Tests

- 같은 10명 입력에 대해 후보 조합 6개가 표시된다.
- 후보 조합 6개 preview 가 compact 한 형태로 표시된다.
- 모든 후보 조합은 각 팀이 1탱 2딜 2힐 구성을 만족한다.
- 모든 후보 조합에서 같은 플레이어가 중복 배정되지 않는다.
- 후보 목록은 점수 차이, 언랭 분배 차이 기준으로 정렬된다.
- 총점 차이가 같은 후보들 사이에서는 역할군별 점수 차이 합이 더 작은 후보가 먼저 표시된다.
- 그 조건도 같으면 탱커 점수 차이가 더 작은 후보가 먼저 표시된다.
- 언랭/브론즈/실버/골드/플래티넘/다이아/마스터/그랜드마스터가 지정한 배경색 규칙으로 구분된다.
- 사용자가 후보 1개를 선택하면 최종 편집 영역에 해당 후보가 로드된다.
- 사용자가 두 슬롯을 클릭하면 두 플레이어가 서로 스왑된다.
- 스왑 직후 화면이 즉시 갱신된다.
- 메인 UI 에서는 숫자 점수가 기본적으로 표시되지 않는다.
- 사용자가 플레이어별 역할 선호도 순서를 입력하거나 수정할 수 있다.
- 역할 선호도 정보가 후보 계산 또는 최종 팀 구성에 반영된다.
- 플레이어 티어 정보를 저장할 수 있다.
- 저장된 플레이어 목록에서 10명을 선택해 현재 매치 입력으로 불러올 수 있다.
- 헤더 행이 있는 입력과 없는 입력 모두 정상 처리된다.

## Non-Goals

- 이번 라운드에서는 모바일 최적화를 필수로 요구하지 않는다.

## Definition Of Done

- 기존 단일 최적 팀 추천 기능이 유지된다.
- 후보 조합 6개 기능이 유지되고, 각 후보의 compact preview 가 빠르게 비교 가능하게 표시된다.
- 선택한 후보를 최종 편집 영역으로 불러온 뒤 클릭 기반 스왑 수정이 가능하다.
- 메인 UI 에서는 숫자 점수 노출 없이도 후보를 파악하고 수정할 수 있다.
- 역할 선호도, 플레이어 저장, 저장된 플레이어 중 10명 선택 기능이 현재 iteration 결과물에 포함된다.
- README 와 FINAL_OUTPUT 에 새 기능과 검증 방법이 반영된다.
